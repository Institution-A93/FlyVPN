# ADR-0023: Симметричная топология узлов — двунаправленный РФ↔загран

- Статус: proposed
- Дата: 2026-06-25
- Связи: amends ADR-0003 (Hetzner egress), ADR-0004 (Selectel ingress), ADR-0006
  (ASN-split) · переутверждает ADR-0015 (sing-box mesh — теперь явно симметричный)

## Контекст

Продукт обслуживает два сегмента: **РФ-юзеры** (зарубежный трафик → зарубежный выход)
и **диаспора за пределами РФ** (доступ В РФ → выход в РФ, тот же VPN наоборот). Жёсткое
разделение ingress(РФ)/egress(загран) больше не держится: юзер за рубежом должен
достать РФ-ресурс через РФ-выход на том же VPN.

## Решение

- **Роли узлов сходятся.** Не «ingress vs egress», а один параметризованный узел =
  **регион (РФ / загран) + способность быть входом и выходом**. Роль определяется на
  сессию по нужному выходу.
- **Двунаправленность.** РФ-юзер → загран-выход; диаспора → РФ-выход. Трансграничный
  хоп — sing-box Reality в **обе** стороны.
- **IaC:** раздельные Ansible-роли `ingress`/`egress` сходятся в одну
  параметризованную роль **`node`** (регион + capability).
- **Оркестратор:** реестр/провизия по региону; выбор exit-узла по направлению юзера.
- **Entitlement:** в какие exit-регион(ы) юзер вправе — атрибут/группа в
  `auth_credentials` (своя схема, ADR-0021; не canonical radcheck).
- **Routing:** ASN/GeoIP-split становится **двунаправленным** per-user/per-direction
  policy.
- **Data plane:** sing-box mesh (ADR-0015) изначально двунаправленный → это
  **расширение, не переписывание**.

## Последствия

`ingress`/`egress` перестают быть привязаны к региону жёстко (amends 0003/0004);
ASN-split — двунаправленный (amends 0006); mesh переутверждаем как симметричный
(0015). AAA-плоскость и операторская панель почти не затронуты — exit-регион это
маршрутизация/выбор узла, не аутентификация.

## Открытые места

- Политика выбора exit-узла (ближайший/по подписке/по нагрузке).
- Ёмкость и масштабирование по регионам.
- Со-локация vs раздельные флоты РФ-выходов и загран-выходов.

## Реализация (статус)

- ✅ **Сплит параметризован**: ingress sing-box использует `self` rule_set (свой
  регион → direct) через `ingress_self_ruleset` (РФ-вход = `ru`; загран-вход ставит
  свой локальный набор). Один шаблон служит обоим направлениям; рендер JSON проверен.
- ✅ Exit-цель уже переменная (`ingress_egress_server`) — РФ-вход → загран-выход,
  загран-вход → РФ-выход.
- ✅ **Симметрия флота — на уровне ролей готова.** entry = роль `ingress`
  (регион-параметризована: `ingress_self_ruleset`); exit = роль `egress`
  (регион-агностична — проверено: чистый Reality-сервер + direct, без РФ/загран-
  допущений). Симметрия достигается **развёртыванием обеих ролей в ОБОИХ регионах**:
  РФ-вход + РФ-выход + загран-вход + загран-выход. РФ-юзер → загран-выход; диаспора →
  РФ-выход. «Узел = регион + роль» выражается инвентарём/group_vars (топология деплоя),
  без слияния кода ролей.
- ⏳ **Отложено (со-локация, нодовое):** «один узел = и вход, и выход» одновременно
  (комбинированный sing-box: TUN-inbound + Reality-server-inbound + routing по
  inbound-tag) и слияние TF-модулей `ingress`/`egress` — оптимизация плотности, НЕ
  требование MVP; валидируется только на узле. Провизия `self`-ruleset для не-РФ
  региона — скрипт по образцу `update-ru-ruleset.sh` (когда появится загран-вход).
